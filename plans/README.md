## Direction: decisions for the maintainer, not planned

- **Alert and digest both carry the same tier changes.** `ALERTS_ENABLED=true`
  is set locally (name checked, value not echoed); if production matches, the
  5 AM alert and the 6 AM digest report identical moves an hour apart. The
  alert is opt-in and the digest is the heartbeat, so this is by design — but
  worth a deliberate choice: keep both, or set `ALERTS_ENABLED=false` and let
  the digest be the single morning email now that it lists changes and (after
  014) the book. No code change needed either way.
- **The digest rebuilds the whole screen to send a summary.** The route
  comment (`app/api/digest/route.ts:40-41`) already calls this the real fix;
  `maxDuration = 300` buys the time. Not worth doing until the run time
  actually threatens the limit.

## Found during the tier_history rebuild (2026-09-24) — now plan 017

- **`scripts/replay-tiers.ts` can mix live and replayed rows in one session.**
  Its upsert guard (`WHERE tier_history.source <> 'live'`) only protects rows
  that already exist. A ticker in the replay's theme set but missing from a
  live snapshot is INSERTED as `replay` into that live session. The two paths
  filter liquidity differently, so the sets differ. Observed: a replay run on
  2026-09-24 inserted one row each into six live sessions. `previousTiers` then
  labels the session `replay` (`bool_and(source='live')`), which suppresses the
  next alert and makes the digest report "baseline not comparable". Fix: skip
  any session that already has live rows, or add a `--from/--to` write window.
  S effort, HIGH confidence. The audit's "no session mixes" check catches it
  after the fact.

## Environment gotcha: worktree base commits

Executor worktrees in this environment are cut from the **session's original
base commit**, not from current `master`. Twice this produced a false STOP.
Every plan from 005 onward therefore opens with a self-healing setup step
(`git merge --ff-only <sha>`). Keep it, and re-verify a plan's cited line
numbers after a predecessor merges — an inserted block shifts every excerpt
below it. Batch 2 plans that share a file say so in "Depends on" and tell the
executor to re-locate by content.
